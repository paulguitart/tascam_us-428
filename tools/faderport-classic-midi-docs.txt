FaderPort Classic: Packet Messaging
Published July 11, 2018



This SDK applies to this model FaderPort:

 

Overview

This page describes the messaging over USB used on the Faderport to communicate with DAWs
Faderport sends messages using a standard MIDI packet format. This only applies to the original gray single channel FaderPort.
 


Native Mode

To put the faderport into Native mode the following message must be sent.

0x91, 0x00, 0x64
Once in Native Mode the Faderport Messages are as follows:

 

Fader Movements

Fader Movements Messages are sent using two consecutive messages with the Status byte of 0xB0. The two messages for either sending or receiving will look like this:

0xB0, id_byte, data_high Byte
0xB0, id_byte| 0x20, data_low Byte
     or

0xB0, 0x00, 7F
0xB0, 0x00, 3E
There is only one Fader on the Faderport, the ID is 0x00

 

Encoder Movements

Encoder Movements Messages are sent using the Status byte of 0xE0. The data byte from the encoder message using 2s complement coding of 7bit (0x7f is -1, 0x01 is 1). Only the value of the delta range is transmitted for the encoder message.

Typical Encoder message may look like this: 0xE0, 0x00, 7F
There is only one Encoder on the Faderport, the ID is 0x00

 

Switch Movements and LED Feedback

Hardware-tested correction to the original SDK text (September 17, 2026):
Switch input IDs and LED output IDs are different. The original statement that
sending the same message back lights that switch's LED does not match the test.
LED IDs reverse each group of eight switch IDs: LED_ID = SWITCH_ID XOR 0x07.

Device -> host: 0xA0, SWITCH_ID, 0x01 = pressed
                0xA0, SWITCH_ID, 0x00 = released
Host -> device: 0xA0, LED_ID,    0x01 = LED on
                0xA0, LED_ID,    0x00 = LED off

For example, SHIFT sends A0 02 01 when pressed. Send A0 05 01 to light
SHIFT, or A0 05 00 to turn it off. Echoing A0 02 01 lights STOP instead.

The definitions below pair each button's input ID with its OWN LED output ID.
Names use hardware labels; original SDK aliases are noted in comments.

Universal Device Request Message

The faderport will report back information using the Universal Device Request Sys Ex Message F0 7E 7F 06 01 F7

 

In which case the Faderport will respond with the following message

     u8 responseData[] = {         0xF0,

                                               0x7E,

                                               0x7F,

                                               0x06,

                                               0x02,

                                               0x00, //manuf ID

                                               0x01, //add two bytes since manuf ID == 0

                                               0x06,

                                               0x02, // family

                                               0x00,

                                               0x01, // member

                                               0x00,

                                               /*0x01,//*/FIRMWARE_VERSION_CHAR0,                                 

                                               /*0x00,//*/FIRMWARE_VERSION_CHAR1,

                                               /*0x00,//*/FIRMWARE_VERSION_CHAR2,

                                               /*0x01,//*/FIRMWARE_VERSION_CHAR3,

                                               0xF7};
